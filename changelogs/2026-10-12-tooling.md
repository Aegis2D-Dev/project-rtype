## Summary
The game gets the same code style and static analysis as the engine, so both
repositories read the same and the pull request checklist (`tools/format.sh`,
`tools/lint.sh`) can be ticked here too. The CI that runs them comes next.

## Added
- `.clang-format`: the engine's style (LLVM base, 4-space indent, 100 columns).
- `.clang-tidy`: the engine's checks (bugprone, cert, clang-analyzer, cppcoreguidelines,
  modernize, performance, warnings as errors), limited to the game's own headers
  (`game/`, `server/`, `client/`, `tests/`); the engine and the other dependencies in
  `build/_deps` are excluded.
- `.editorconfig`: UTF-8, LF, final newline, 4 spaces (2 for JSON, YAML and Markdown).
- `tools/format.sh` (`--check` for CI) and `tools/lint.sh [build-dir]`: run clang-format on
  every tracked C++ file, and clang-tidy on every tracked `.cpp` of the compilation
  database, as in the engine.
- `tools/requirements.txt` (clang-format and clang-tidy 22.1.8) and
  `cmake/requirements.txt` (Jinja2, needed by the engine's glad for client builds).

## Changed

- Usage: `pip install -r tools/requirements.txt` in the `.venv`, then
  `tools/format.sh` (or `--check`) and, after a build with
  `CMAKE_EXPORT_COMPILE_COMMANDS` (on in every preset), `tools/lint.sh build/<preset>`.
